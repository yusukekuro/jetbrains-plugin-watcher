## 廃止の記録（2026-11-11）

- **理由**: JetBrains プラグイン（ID 19099）のダウンロード数・評価の LINE 通知が不要になったため。
- **廃止時点の状態**: 1 時間ごとに起動していて、エラーもなく正常に動いていた（最終値 `Downloads: 3566, Rating: 3.1`）。ランタイムは Node.js 18（サポート終了済み）のままだった。
- **削除したもの**（`samconfig.toml` のとおり ap-northeast-1）:
  - CloudFormation スタック `jetbrains-plugin-watcher` と、その中身（Lambda `WatcherFunction`、EventBridge ルール `rate(1 hour)`、IAM ロール、DynamoDB テーブル `WatcherMessage`、Secrets Manager の `lineAccessToken` / `lineUserId`）
  - CloudWatch のロググループ `/aws/lambda/jetbrains-plugin-watcher-WatcherFunction-*` と、旧名のときの残骸 `/aws/lambda/jetbrains-plugin-downloads-watcher-WatcherFunction-*`
  - SAM のデプロイ用 S3 バケット（`aws-sam-cli-managed-default` スタックのもの）の `jetbrains-plugin-watcher/` 配下
- **残したもの**:
  - LINE の Messaging API チャネル。`manga-watcher`・`actress-watcher` と共有しているため消していない（アクセストークンも同じ）。このプロジェクト専用の LINE 資源は無い。
  - 送信済みの LINE メッセージ。
  - このリポジトリ（GitHub ではアーカイブ済み）。
- **削除でつまずいた点**: スタックを削除すると Secrets Manager のシークレットが Lambda より先に消える。すると Lambda の削除時に `{{resolve:secretsmanager:...}}` を解決できず、`DELETE_FAILED` になった。
  Lambda を `aws lambda delete-function` で直接消してから、`aws cloudformation delete-stack --retain-resources WatcherFunction` で削除し直して片付けた。
  同じ構成の `manga-watcher`・`actress-watcher` を消すときも同じことが起きるはず。
- **復活させるなら**: `sam build && sam deploy` でもう一度作れる。ただしテンプレートのシークレットの値はダミー（`dummy-value`）で、Lambda の環境変数にはデプロイした時点の値が入る。
  あとからシークレットだけ書き換えても、テンプレートが変わらないので再デプロイは「変更なし」になり、Lambda には反映されない。
  `sam build` の成果物（`.aws-sam/build/template.yaml`。git 管理外）の `SecretString` だけを本物の値に差し替えてから `sam deploy` する。

This SAM application uses several AWS resources. These resources are defined in the `template.yaml` file in this project.

- Lambda function (WatcherFunction)
  - Triggered by EventBridge
  - Calls jetbrains API to fetch the plugin info. Stores the summary in DynamoDB. When the summary is changed, push the summary to your LINE account.
  - Even if the summary is not changed, it still sends the summary to LINE every day at 10AM JST.
    - This 10AM check has been removed. See the commit "Remove is10AMNow".
- DynamoDB (WatcherMessage)
  - Stores a key "previousMessage"
- EventBridge (WatcherFunctionEvery1HourSchedule)
  - Every 1 hour, triggers the lambda function (it was every 5 minutes until 2025-01-13)
- SecretsManager
  - Stores LINE Access Token and LINE User ID

## Folder structure

This project contains source code and supporting files for a serverless application that you can deploy with the SAM CLI. It includes the following files and folders.

- handler - Code for the application's Lambda function written in TypeScript.
- events - Invocation events that you can use to invoke the function. It simulates an event coming from EventBridge to the lambda function.
- handler/tests - Unit tests for the application code. 
- template.yaml - A template that defines the application's AWS resources.

## Commands

To build the application, use `sam build`.

The SAM CLI installs dependencies defined in `handler/package.json`, compiles TypeScript with esbuild, creates a deployment package, and saves it in the `.aws-sam/build` folder.

```bash
sam build
```

To deploy the application, use `sam deploy`.

```bash
sam deploy
```

To simplify troubleshooting, SAM CLI has a command called `sam logs`. `sam logs` lets you fetch logs generated by your deployed Lambda function from the command line. In addition to printing the logs on the terminal, this command has several nifty features to help you quickly find the bug.

`NOTE`: This command works for all AWS Lambda functions; not just the ones you deploy using SAM.

```bash
sam logs -n WatcherFunction --stack-name jetbrains-plugin-watcher --tail
```

To delete the sample application that you created, use the AWS CLI. Assuming you used your project name for the stack name, you can run the following:

```bash
sam delete --stack-name jetbrains-plugin-watcher
```

## Unit tests

Tests are defined in the `handler/tests` folder in this project. Use NPM to install the [Jest test framework](https://jestjs.io/) and run unit tests.

```bash
jetbrains-plugin-watcher$ cd handler
handler$ npm install
handler$ npm run test
```
